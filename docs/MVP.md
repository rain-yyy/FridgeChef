# 冰箱管家 · MVP

## 技术基础
- iPhone，iOS 17+，Swift + SwiftUI
- SwiftData 本地存储，无后端
- AI：OpenRouter API（可切换模型），API key 存 Keychain
- 中英文双语（String Catalog）

## 第一阶段（MVP）

> 实现以 `docs/design-spec.md`（v0.2 定稿）为准；下面已按定稿更新了与旧描述冲突的条目。

### 第 2 步：库存管理 ✅
- [x] 冰箱库存页：顶部「尽快用掉」（冷藏且 ≤2 天，含已过期），其余按分类分组；显示名称、数量单位、位置、剩余天数
- [x] 剩余天数颜色 + 文字标识：已过期 N 天 / 今天、明天过期、剩 2 天（快过期，带闹钟图标）/ 剩 N 天（正常，不上色）/ 冷冻（雪花图标）
- [x] 筛选：全部 / 冷藏 / 冷冻；按名称搜索；组内按剩余天数排序，冷冻排最后
- [x] 左滑删除、点击编辑、"+" 添加；空状态；搜索无结果提示
- [x] 添加 / 编辑页：名称、分类、位置、数量（步进 0.5）、单位、添加日期、过期日（冷藏自动计算可改、可恢复默认，冷冻隐藏）；「保存并继续添加」；删除带确认
- [x] 保质期：先按名字预设（如西红柿 7 天），再按分类默认（肉 3 / 半成品 5 / 蔬菜 5 / 蛋奶 7）
- [x] 冷冻改冷藏时从当天重新计算过期日

### 第 3 步：AI 菜单推荐 ✅
- [x] 设置页：OpenRouter API Key（钥匙串，可显示 / 隐藏）、模型 ID + 常用模型、测试连接、关于（按定稿不放默认菜系和人数）
- [x] 做饭页：中餐 / 西餐、1–10 人（记住上次选择），展示快过期食材；已过期的不参与推荐；未设置 Key 时提示并禁用生成
- [x] 把未过期库存（快过期优先、冷冻也算）发给 AI，用严格 JSON schema 要求固定返回 3 个方案，返回后逐项校验
- [x] 推荐结果页：2–3 个方案，含菜名、食材及用量，标注快过期食材，按用到的快过期食材数排序；可重新生成；结果持久化，重启后可「查看上次推荐」
- [x] 加载状态（骨架卡片）、错误状态（无 key、网络失败、AI 返回异常 / Key 无效 / 模型不可用等）
- 常用模型（2026-10 实测都能稳定返回 JSON）：`anthropic/claude-haiku-5.5`（默认）、`openai/gpt-6-luna`、`deepseek/deepseek-v4.1-flash`（较慢，15–25 秒）

### 第 4 步：做完扣减 ✅
- [x] 方案详情页：每道菜的冰箱食材和用量、需另备的调料、步骤，"做完了"按钮
- [x] 确认扣减页：逐项可勾选、±0.5 微调，显示扣减后剩余量
- [x] 剩余不足 0.25 自动移除；确认后回到冰箱页并提示

### 第 5 步：收尾
- [x] 补全中英文翻译（含英文单位单复数）
- [x] 深色模式检查（文字对比度按 WCAG 校验，已调整「已过期」和禁用文字的深色值）
- [x] 动态字体检查（最大字号下卡片改为上下排列、圆形编号随字号缩放）
- [x] 修复 Release 构建（#Preview 只在 DEBUG 编译）
- [ ] 自己日常使用测试，记录问题
- [ ] 深色配色最终效果调整（目前为按浅色推算的版本）

### 已知限制（日常使用时留意）
- 生成菜单后如果改了某个食材的单位，扣减时用量仍是 AI 按旧单位给的数字
- 英文界面下 AI 会用英文写菜名，但食材名仍是录入时的语言
- App 在主屏幕上的名字中英文都是「FridgeChef」（未本地化显示名）
