# TICKETS.md — 任务清单（P0/P1 详细，P2–P4 为 Epic）

> 使用规则见 `PLAN.md §17`。每个 ticket 必须先由 agent 输出实现计划、经你确认后再写代码。

## P0 · 基础

### T0.1 仓库与环境（S）
**目标**：monorepo 骨架可运行。
**范围**：目录按 `PLAN §4.6`；`supabase init`，本地 `supabase start` 可用；Xcode 工程（SwiftUI，iOS 17，SPM 引入 `supabase-swift`，锁定版本）；xcconfig 区分 Debug/Release；SwiftLint；GitHub Actions 骨架（lint + 空测试）；`.gitignore` 覆盖 `.env`、xcconfig 私有值。
**AC**：1) 干净克隆后按 README 能启动本地 Supabase；2) App 在模拟器运行，并能调用本地 Supabase 的健康检查；3) CI 绿。
**不做**：任何业务功能。 **依赖**：O-10。

### T0.2 Schema v1 迁移（M）
**目标**：把 `SCHEMA.sql` 的 P0 部分变成正式 migrations。
**范围**：按主题拆成多个 migration（枚举与扩展 / 用户与 household / 字典 / 库存 / 菜谱与其余 / 函数 / RLS 与 grants / 参考数据）；**内容以 `SCHEMA.sql` 为准，不得擅自改动语义**。
**AC**：1) 从零应用全部迁移成功；2) `SCHEMA_SMOKE_TEST.sql` 的断言移植为 pgTAP 后全绿；3) 每张 `public` 表已启用 RLS（有测试断言）；4) 在真实 Supabase 上验证 `auth.users` 触发器生效（S3 联动）。
**风险**：`SCHEMA.sql` 仅在裸 PG16 + 模拟 auth 上验证过。 **依赖**：T0.1。

### T0.3 RLS 与权限测试（M）
**目标**：用测试而不是肉眼保证隔离。
**范围**：pgTAP 覆盖 `PLAN §11.1` 矩阵的每一格：用户 A/B 交叉读写、anon 全拒、`usage_ledger` 客户端不可见、`merge_ingredients` 客户端不可调用、字典/菜谱客户端只读。
**AC**：矩阵每一行至少一个正向和一个反向用例；CI 执行。 **依赖**：T0.2。

### T0.4 字典种子（L，含你的人工时间）
**目标**：约 300 种食材入库，可直接支撑 P1 匹配。
**范围**：`pipeline/seed-dictionary`：LLM 按类别分批生成（标准名中/英、别名含英美用词、类别 slug、默认存放位置、保质期覆盖、默认单位/数量、是否常备）→ 脚本校验（必填、slug 唯一、别名冲突、保质期非负）→ 输出 `dictionary_seed.json` → **你通读校对（O-06）** → 导入。覆盖规则见 `PLAN §5.4`（含北美/欧洲超市常见食材）。
**AC**：≥300 条；每条有类别和默认单位；Top-100 有默认保质期（或明确继承类别）；别名无冲突；导入后冒烟测试仍全绿；`dictionary_meta.version` 已递增。
**依赖**：T0.2、O-06、O-07（LLM）。

### T0.5 登录（Sign in with Apple）（M）
**目标**：真机可登录，会话持久。
**范围**：原生 Apple 登录（含 nonce）→ `signInWithIdToken`；会话持久化与自动刷新；登出；取消/失败状态；登录后读取 profile。
**AC**：1) 真机新用户登录后 DB 中出现 profile + 个人 household + owner 成员；2) 杀进程重开仍是登录态；3) 登出后回到登录页；4) 用户取消不报错。 **依赖**：T0.1、T0.2、S3。

### T0.6 App 外壳（S）
**目标**：导航与基础设施。
**范围**：`TabView`（库存/做什么占位/设置）；`Loadable<T>`、`AppError`、`Clock`、`LocalDate`（含 Codable `yyyy-MM-dd`）；设计 token；String Catalog；深色模式；空状态组件。
**AC**：`LocalDate` 与 `Clock` 有单元测试（含月末、闰年、夏令时日）；所有文案来自 String Catalog。 **依赖**：T0.1。

### T0.7 字典本地缓存与搜索（M）
**目标**：整本字典本地缓存，联想即时。
**范围**：`DictionaryStore`：读 `dictionary_meta.version` → 不同则整本重拉（分页 1000）→ 文件缓存 → 内存索引；搜索排序（精确 > 前缀 > 子串，频次与类别做次序）；`merged` 解析到 `merged_into`。
**AC**：1) 冷启动无网络时仍能用上次缓存搜索；2) 固定用例表（查询→期望首选）单元测试通过，如 `西红柿→番茄`、`青菜→上海青`、`coriander→香菜`；3) 版本变化后自动更新；4) 1000 条食材 + 4000 别名下键入延迟无感（<16ms 量级，用 Instruments/测量确认）。 **依赖**：T0.4、T0.6。

### T0.8 库存列表（M）
**目标**：S03 屏幕。
**范围**：`InventoryRepository`（协议 + Supabase 实现 + Fake）；`InventoryStore`（乐观更新 + 回滚）；按食材聚合；分组切换（位置/到期）；搜索；到期徽标（图标+文字+颜色）；左滑"用完了/丢弃"；"已过期，请检查"区（丢弃/仍在用）；回到前台刷新。
**AC**：1) 多批次聚合正确，单位不同则显示"N 批"；2) 过期批次不在主列表且不参与后续匹配；3) 写失败会回滚并提示；4) VoiceOver 可读；5) 聚合/分组逻辑有单元测试。 **依赖**：T0.5、T0.6。

### T0.9 添加食材 + 批量添加（L）
**目标**：S05/S06，"3 次点击"目标。
**范围**：搜索联想 → 预填默认单位/数量/存放位置/到期日（`purchased_on + 保质期`，客户端算，且与服务端 `suggest_expiry` 有一致性测试）→ 保存并继续；批量模式：常用/最近食材 chips → 暂存区 → 全部保存；英制输入（lb/oz/fl oz/gal）换算为 g/ml 存储；更换存放位置时询问是否重算到期日；无匹配时出现"添加「X」"行（接 T0.10）。
**AC**：1) 常见食材从打开 App 到保存 ≤3 次点击；2) 批量录入 10 件 ≤2 分钟（人工计时，附记录）；3) 到期日计算与 `suggest_expiry` 在一批用例上完全一致；4) 单位换算有单元测试；5) 保存写入 `inventory_items` 且触发器记录 `added` 事件。 **依赖**：T0.7、T0.8。

### T0.10 未知食材解析（`resolve-ingredient`）（L）
**目标**：字典之外的食材由 LLM 判定别名/新增/拒绝。
**范围**：Edge Function（契约见 `PLAN §9.1`）；`_shared`：LLM provider 接口（先接 O-07 指定的一家）、Zod、配额检查、`usage_ledger` 写入、错误信封；候选检索（`strpos` + `pg_trgm`）；落库规则（`alias_of` ≥0.8 → 别名 `source='llm'`；`new` → `status='auto'`；`not_food`/低置信度 → 拒绝）；否定缓存；输入规范化；客户端集成（S05 的"添加「X」"）。
**AC**：1) 100 条评测集正确率 ≥90%、非食品拒绝率 100%、注入串 0 次生效（`PLAN §10.3`）；2) 超日配额返回 `429 quota_exceeded`；3) LLM 输出不合法时重试 1 次，仍失败则报错且**不写库**；4) 每次调用有 `usage_ledger`；5) CI 里用录制夹具，不真调 LLM。 **依赖**：T0.4、O-07。

### T0.11 食材详情与批次编辑（S）
**目标**：S04。**AC**：可编辑数量/位置/到期日/备注；编辑触发 `edited` 事件；数量减少触发 `consumed_partial`；状态变更触发 `used_up`/`discarded`/`restored`（与冒烟测试 D6 一致）。 **依赖**：T0.8。

### T0.12 设置（M）
**目标**：S07 + 引导 S02。
**范围**：常备品管理（`household_staples`，默认值来自 `is_staple_default`）；提醒时间/提前天数；单位偏好（仅显示）；地区；反馈入口；免责声明页（保质期仅为估计）；登出；删除账号（占位，P4 实现）；引导流程。
**AC**：改常备品后，重新计算的匹配结果随之改变（P1 联调验证）；所有设置写回 `profiles`/`household_staples` 并持久。 **依赖**：T0.5。

### T0.13 到期提醒（M）
**目标**：每日汇总本地通知。
**范围**：`DigestPlanner`（纯函数）+ `DigestScheduler`（封装 `UNUserNotificationCenter`，可替换）；未来 30 天、≤60 条；标识符 `digest-*`；重排触发点（前台、库存变更、设置变更、BGAppRefreshTask）；权限时机（首次保存食材后）；被拒绝时的可见提示与跳转设置。
**AC**：1) 用假 Clock 的单元测试覆盖：0 批次、200 批次、跨月、夏令时切换日、`digest_hour` 已过；2) 真机手测：把到期日设为明天，次日早晨收到通知；3) 关闭权限时库存页有可见提示；4) 文案最多列 3 个食材名 + "等 N 样"。 **依赖**：T0.8、S4。

### T0.14 最小可观测性（S）
**目标**：出问题能查。
**范围**：Edge Function 结构化日志（不含敏感信息）；`usage_ledger` 视图（日成本、按功能、按用户）；iOS `os.Logger` 与 MetricKit；TestFlight 崩溃报告确认可见。
**AC**：能用一条 SQL 回答"今天各功能花了多少钱/多少次"；日志里搜不到任何令牌或原始图片。 **依赖**：T0.10。

### T0.15 Dogfooding 与 Gate A（S）
**目标**：验证 P0 出口。
**AC**：`PLAN §3.3` 的 6 条全部满足并留证据（计时记录、评测结果、RLS 测试报告、7 天使用日志）。 **依赖**：T0.3–T0.14。

## P1 · 核心闭环（= MVP）

### T1.1 菜谱相关迁移（S）
**目标**：`recipes`/`recipe_ingredients`/`recipe_aliases`/`recipe_reports`/`cooked_log`/`recipe_requests` 与 RLS、索引正式化（若 T0.2 已含则本 ticket 仅补测试）。
**AC**：pgTAP 覆盖菜谱只读、报错与请求仅自己可写/读；`hidden` 菜谱客户端不可见。 **依赖**：T0.2。

### T1.2 管线脚手架（M）
**目标**：`pipeline/` 与 `supabase/functions/_shared/` 共用的基础模块（D75）。
**范围**：配置加载；LLM provider 接口（复用 T0.10）；Zod 模式（§7.2 候选 JSON）；字典解析器（复用 `resolve-ingredient` 的逻辑）；礼貌抓取器（robots.txt、每域名间隔、UA、超时、大小、重定向白名单、SSRF 防护）；`usage_ledger` 写入；幂等 upsert 工具；日志。
**AC**：抓取器有测试（私有 IP 被拒、非白名单重定向被拒、超大响应被截断、robots 禁止时不抓）；模块可同时被 CLI 与 Edge Function 引用。 **依赖**：T0.10。

### T1.3 菜名清单与覆盖分析（M）
**目标**：`dish_list.json`（≈300）。
**范围**：LLM 生成 → **覆盖分析脚本**（Top-100 食材每种 ≥5 道；类别配比见 `PLAN §7.3`；≥30% 用北美/欧洲常见食材）→ 打印缺口 → 按缺口补菜名 → 你筛选定稿。
**AC**：脚本输出覆盖报告，缺口为 0 或有明确说明。 **依赖**：T0.4。

### T1.4 检索与抓取（M）
**目标**：菜名 → 1–3 个来源页正文。
**范围**：`site:` 限定的检索（供应商依 S2/O-11）；用 T1.2 抓取器；正文清洗（去脚本/广告/导航）；只保留 URL 与 hash，不长期存原文。
**AC**：对 30 个菜名，≥80% 至少得到 1 个可解析来源；失败原因分类记录；录制夹具用于测试。 **依赖**：T1.2、S2。

### T1.5 抽取与角色标注（L）
**目标**：页面文本 → 候选 JSON。
**范围**：结构化输出；prompt 含 §7.4 rubric 与注入防护；食材名保留原写法待归一化；用量字段规则（"少许/适量"→`to_taste`）。
**AC**：30 道黄金集：main 召回 ≥95%、precision ≥90%；aux/seasoning 一致率 ≥85%；注入用例 0 次生效；评测脚本可重复运行并输出报告。 **依赖**：T1.2、S5、黄金集（你标注）。

### T1.6 归一化（S）
**目标**：候选食材 → 字典 id。
**AC**：解析不了的食材阻断入库并写入待处理清单；品牌名被替换为通用食材（如"李锦记蚝油"→蚝油）；合并重复食材规则（角色取重要者、同单位数量相加）有测试。 **依赖**：T1.5、T0.10。

### T1.7 重写与近似度检测（M）
**目标**：落实 D34。
**范围**：步骤重写；6-gram 重叠率 >0.25 或 ≥20 字公共子串 → 判不合格，重试 1 次，仍不合格则丢弃并记录。
**AC**：构造"原样复制""轻微改写""充分改写"三类样本，检测结果符合预期；阈值可配置。 **依赖**：T1.5。

### T1.8 校验器与入库（M）
**目标**：`PLAN §7.6` 的 V1–V12 与幂等入库。
**AC**：每条规则至少一个反例测试；重复运行不产生重复菜谱（按 `slug`/`content_hash`）；入库状态 `unverified`；`raw_or_undercooked` 标记生效；写 `usage_ledger`。 **依赖**：T1.6、T1.7。

### T1.9 Pilot：20 道端到端（M）
**目标**：先小样本跑通并冻结管线 v1。
**AC**：20 道全流程完成；你人工核对角色错误率可接受（在 T1.5 阈值内）；记录**每道平均成本与耗时**；问题清单回灌 prompt/规则；M4 达成。 **依赖**：T1.4–T1.8。

### T1.10 批量运行 300 道（M）
**目标**：放量。
**范围**：失败重试队列；成本上限保护；断点续跑；成本与失败原因报告。
**AC**：≥300 道入库（含 `unverified`）；失败清单有原因；总成本在预估内。 **依赖**：T1.9、**O-08（来源条款复核已写入 `docs/SOURCES.md`）**。

### T1.11 审核（L，主要是你的时间）
**目标**：100% 审核角色。
**范围**：`pipeline review` CLI（通过/改角色/拒绝/跳过，记录 `verified_by/verified_at`）。
**AC**：≥300 道 `verified`；Top-100 食材每种 ≥5 道；审核统计报告。M5 达成。 **依赖**：T1.10、O-05。

### T1.12 匹配 RPC 与评测（M）
**目标**：`match_recipes` 正式化 + 评测集。
**范围**：移植规则与夹具（`PLAN §6`）；20 个冰箱场景 JSON（`PLAN §12.2`）+ 评测脚本。
**AC**：1) pgTAP 覆盖：过期排除、常备覆盖、至少 1 个核心在库、`hidden` 排除、排序稳定；2) 20 场景前 5 条合理率 ≥80%（Gate B）；3) 300 菜谱 × 500 库存行 p95 <300ms（附 `EXPLAIN ANALYZE`）。 **依赖**：T1.11、T0.8。

### T1.13 推荐页（M）
**目标**：S08。
**范围**：调用 `match_recipes`（传本地日期）；两段列表；卡片信息；未审核标签；过滤与空状态（解释原因、引导多录入）。
**AC**：与 T1.12 夹具在 App 内一致；`p_today` 来自 `Clock`；下拉刷新；无结果时的引导文案。 **依赖**：T1.12。

### T1.14 菜谱详情（M）
**目标**：S09。
**范围**：食材按角色分组，叠加 ✓有/✗缺/常备（用本地库存 + 字典）；步骤与可选计时器；"参考来源"链接（`source_url`）；"报错"（写 `recipe_reports`）；`raw_or_undercooked` 提示；未审核标签；免责声明。
**AC**：`unsafe` 报错可提交；来源链接可打开；无 `source_url` 时不显示该入口；VoiceOver 可读。 **依赖**：T1.13。

### T1.15 菜名搜索与未命中记录（S）
**目标**：S11。
**AC**：按标题+别名（`pg_trgm` + `strpos`）搜索；未命中写 `recipe_requests` 并提示"记下来了，之后会补"；命中直接进详情。 **依赖**：T1.1、T1.14。

### T1.16 做了这道菜（扣减）（M）
**目标**：S10。
**范围**：列出用到的库存批次（FEFO 预选）；每项"用了一部分"（stepper，默认剩余 50%）/"用完了"；写 `cooked_log`；5 秒撤销（回滚库存变更与日志）。
**AC**：1) 事件正确写入 `inventory_events`；2) 撤销后库存与事件回到操作前（或写 `restored`）；3) 不做跨批次/跨单位自动计算；4) 有 ViewModel 单元测试（多批次、单位不同、撤销）。 **依赖**：T1.14、T0.11。
